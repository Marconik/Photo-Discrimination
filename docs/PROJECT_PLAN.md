# Photo-Discrimination 项目规划

更新时间：2026-11-09。以当前“先界面和搜索”的需求为准。

## 产品流程

选择并下载识别工具 → 选择本地文件夹 → 勾选照片 OCR 并保存文字 → 点选预览 → 按空格分隔关键词搜索 → 勾选照片移动导出到新文件夹。

## 当前版本已实现

- Python / PySide6 原生桌面界面；当前在本机 Python 3.10、PySide6 6.8.2.1 验证。
- 导入当前文件夹内 JPG/JPEG、PNG、WebP、BMP；不递归子目录。
- 列表点选照片、异步预览、缩放、打开原图、查看/复制/编辑文字。
- 每行末尾勾选框；勾选状态独立于预览和搜索，显示被筛选隐藏的勾选数量。
- 相册内 OCR.json 读写，一张照片映射一个无空白文字串；再次保存覆盖本张旧结果。
- 关键词以 Unicode 空白分隔，全部命中、顺序不限；忽略英文大小写、统一全角半角；保留符号的字面匹配。
- 仅检索 OCR 文本，暂不按照片文件名搜索；输入为空显示所有照片。
- 已接入 PaddleOCR；设置中明确选择 CPU/GPU、GPU CUDA 构建与轻量/高精度模型，点击下载完成验证后启用。首次启动不自动下载任何模型或配置 API。
- 识别复用一个独立进程内的模型实例，逐张移除结果空白并保存；失败保留旧字、成功空结果覆盖为空串，支持停止。
- 勾选照片批量移动到新目录，目标 OCR.json 继承对应文字，源索引移除已成功移动条目。
- 启动入口 start.bat；可选命令行相册参数；README 提供操作说明。

## OCR.json 约定

UTF-8 对象，键为当前文件夹照片的完整文件名，值为字符串。例如：

```json
{
  "东京旅行.jpg": "東京駅2026年予約番号ABC-123",
  "购物小票.png": "发票金额￥200Coffee"
}
```

无条目表示暂无结果；空字符串表示已保存且无文字。导入只读取，不自动创建 JSON；首次保存文字或执行移动时创建。读取时移除文本空白，写入时将规范化结果持久化；保留原有字符，不自动修改大小写或全角形式。搜索另行执行 NFKC 与 casefold。

损坏 JSON、重复键、非字符串值必须报错并保留文件。JSON 原子替换保存；通过比较原始字节检测常见外部修改，不使用 SHA256。暂不支持同一相册多实例并发写入。缺失照片的旧条目保留，不自动清理用户索引。

## 勾选与导出规则

- 点击列表行只切换预览，不改变勾选。
- “勾选结果”只增加当前筛选中的照片；“清空勾选”清除全部，包括隐藏项。
- 移动操作包含所有勾选照片，确认框明确显示数量、隐藏项数量、文件列表和目标位置。
- 目标必须是全新文件夹，不覆盖已有文件夹或照片。
- 跨盘通过复制后删除实现移动。逐张先保存目标图片和 OCR.json，再移除原图、更新源索引。
- 失败后停止剩余批次，已完成的移动保持完成；异常时可能保留重复照片或旧源索引条目，错误中说明。先保证副本与文字存在，不做删除式回滚。
- 工作线程进行导入/移动；文件操作期间禁用冲突操作并暂缓关闭窗口。
- 当前实现不移动真实用户照片用于自动验证；测试只操作临时生成文件。

## 代码结构

```text
main.py / start.bat            启动
requirements.txt              固定 PySide6 版本
photo_discrimination/
  album.py                    相册、JSON、文本规则、移动
  models.py                   列表、勾选、搜索代理
  window.py                   窗口、预览、后台操作
  style.py / fonts.py         样式、系统字体兼容
scripts/create_demo.py        生成图片及手工文字演示数据
 tests/                       核心逻辑与 Qt 界面测试
```

相册 JSON、演示数据、缓存、模型与日志不提交 Git。本版本用相册旁 JSON 作为唯一文字数据源；不引入 SQLite 或其他后台服务。

## OCR 部署与验证已完成

1. 运行环境按 CPU / GPU cu118 / cu126 / cu129 隔离在 runtimes/，权重共用 models/；界面环境不安装 OCR 依赖。
2. 本机已验证 GPU cu118，PaddlePaddle 3.2.2、PaddleOCR 3.3.2、PaddleX 3.3.13、PP-OCRv5 mobile 检测与识别模型；显存实测为 4GB，驱动 546.30。
3. GPU 张量计算、检测和文字识别均实际成功，设备为 gpu:0，不使用静默 CPU 回退。
4. 三张演示图片实际生成 OCR.json，验证中英日、数字、符号和多关键词搜索；另经主窗口按钮完整执行两张重新识别。
5. 禁止 Python socket 连接与 DNS 后，从本地权重启动并完成 GPU 推理，网络尝试数为 0。
6. 新增设置和任务验证，当前共 48 项自动测试。模型和安装目录、启用配置、下载缓存不进入 Git。

## 后续工作

继续用真实用户照片评估准确率、竖排和小字表现，以及大规模批处理的时间与显存占用；当前轻量模型通过演示验证，不视为准确率基准。CPU 和其他 CUDA 构建提供下载入口，但本次实际部署仅 cu118。模型文件仍以本地 JSON 索引为数据源；VLM、API 和安装包待后续需求。

## 验证方式与边界

自动测试覆盖搜索语义、Unicode 空白、原子写入失败、损坏/并发修改 JSON、移动中各阶段失败，以及界面导入、预览、勾选、过滤、保存和移动。另使用手工文字演示相册渲染截图检查布局；演示不是 OCR 准确率测试。

实际大规模相册、跨物理磁盘、网络共享目录、硬断电恢复和安装包仍需后续专门验证。当前照片与文本同步采用逐文件提交，不承诺整批移动的跨文件系统原子性。
